# Discovery Checklists — Fintech User Research

Reference for PM Expert skill. Load when reviewing or planning discovery work in fintech.

---

## Research Quality Red Flags

These are signs that discovery work is weak and needs to be challenged:

### Sample Bias
- [ ] All interviewees are existing users (missing non-adopters and churned users)
- [ ] All interviewees are power users or early adopters
- [ ] Recruited through your own channels (survivorship bias)
- [ ] Sample skews young/urban/tech-savvy when TAM is broader

### Question Bias
- [ ] Leading questions ("Would you use a feature that saves you time?")
- [ ] Hypothetical questions ("Would you use X if we built it?") — always say yes
- [ ] Feature validation questions instead of problem exploration
- [ ] No questions about current behavior (what they actually do today)

### Synthesis Bias
- [ ] Quoting memorable anecdotes as if they were patterns
- [ ] Ignoring contradictory data points
- [ ] Mapping findings directly to feature requests
- [ ] No distinction between "nice to have" and "I'd change my behavior for this"

## Strong Discovery Signals (what to look for)

### Behavioral Evidence
- User has already built a workaround (high pain signal)
- User can't remember the last time they did X (low frequency = low priority)
- User's described behavior contradicts their stated preference (stated ≠ revealed)
- Multiple users independently describe the same frustration in similar words

### Fintech-Specific Signals
- User avoids a feature because they don't trust it (trust gap, not UX gap)
- User does a manual step that should be automated (efficiency opportunity)
- User consults another source before acting (information gap)
- User hesitates at a specific moment in the flow (friction/fear/confusion)

## Jobs-to-be-Done Framing for Fintech

### The 3 Jobs in Investment Products
1. **Functional:** "Help me grow my money without losing sleep"
2. **Emotional:** "Make me feel like I'm in control / not being played"
3. **Social:** "Help me be seen as financially smart by my peers"

Most fintech products over-invest in functional, under-invest in emotional and social.

### Trigger Events (when users switch or adopt)
- Life event: marriage, baby, job change, inheritance
- Financial event: bonus, salary increase, market rally
- Social event: friend/colleague started investing, viral moment
- Frustration event: bad experience with existing broker

GTM timing and messaging should map to these triggers — not to feature launches.

## Competitive Research Checklist

When doing a competitive teardown, cover all three layers:

### Layer 1: Surface (what users see)
- [ ] Onboarding flow (steps, friction, time-to-first-value)
- [ ] Core use case UX (how does the key job get done?)
- [ ] Pricing visibility and structure
- [ ] Trust signals (licenses, social proof, transparency)

### Layer 2: System (how it works)
- [ ] Business model (how do they make money?)
- [ ] Distribution channel (how do they acquire users?)
- [ ] Key partnerships (bank, data provider, regulator relationships)
- [ ] Technology stack signals (speed, reliability, API ecosystem)

### Layer 3: Strategy (why they're doing it this way)
- [ ] What segment are they optimizing for?
- [ ] What are they deliberately NOT doing?
- [ ] What would they have to give up to copy what you're doing?
- [ ] What's their 3-year trajectory based on current signals?

The most useful competitive insight is usually in Layer 3 — and it's almost never in app store
reviews or feature comparison tables.
